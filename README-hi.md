# laya-mcp

[Laya](https://github.com/NandhaKishorM/laya) के टाइप किए निर्णयों के लिए MCP सर्वर — `noul` (हाँ/नहीं), `choice`, `score` — जिसे सर्वर के संपर्क में टिकाऊ बनाने के लिए लपेटा गया है।

[English](README.md) · [简体中文](README-zh.md) · [Español](README-es.md) · [Português](README-pt.md) · [हिन्दी](README-hi.md)

```bash
npx -y laya-mcp --help
```

आधिकारिक MCP Registry में [`io.github.PerryLink/laya-mcp`](https://registry.modelcontextprotocol.io/v0.1/servers?search=perrylink) के रूप में पंजीकृत।

> **यह npm पैकेज एक लॉन्चर है, कार्यान्वयन नहीं।** Laya एक PyTorch मॉडल है, इसलिए सर्वर स्वयं Python में है। यह पैकेज स्थापित करने पर आपको Node प्रवेश-बिंदु मिलता है और बस वही; आपको Python पक्ष भी चाहिए:
>
> ```bash
> pip install "laya-mcp[mcp]"
> ```
>
> `npx laya-mcp` वह interpreter ढूँढता है, उसे stdio सौंपता है, और MCP स्ट्रीम को बिना छुए आगे भेज देता है। यह आपके लिए कुछ स्थापित नहीं करता — किसी कमांड को चलाने के अतिरिक्त प्रभाव के रूप में torch (~2 GB) और एक checkpoint (~650 MB) ले आना लॉन्चर का काम नहीं है।

### यदि यह आपका Python न ढूँढ सके

Windows पर PATH में `python` अक्सर Microsoft Store का execution alias होता है, जो एक स्टब है: वह कुछ भी import नहीं कर सकता और आपके असली interpreter से *आगे* बैठा होता है। इसलिए लॉन्चर यह बताता है कि उसने क्या-क्या आज़माया, बजाय यह दावा करने के कि पैकेज नहीं है। दोनों हालत में interpreter सीधे बता दें:

```bash
# सीधे नाम लें
set LAYA_MCP_PYTHON=C:\path\to\python.exe        # Windows
export LAYA_MCP_PYTHON=/path/to/python           # macOS, Linux

# या जिस virtualenv में आपने इसे स्थापित किया उसे सक्रिय कर दें — VIRTUAL_ENV का सम्मान होता है
```

> `LAYACORE_PYTHON` अभी भी पढ़ा जाता है। 0.1.0 और 0.1.1 ने वही नाम त्रुटि संदेश में छापा था, और जो लॉन्चर उस चर का सम्मान करना बंद कर दे जिसे उसके ही पिछले संस्करण ने सेट करने को कहा था, वह पुराना उपनाम रखने वाले से बुरा होगा।

> **स्थिति: 0.1.4, निर्माणाधीन।** Python मूल लागू है और CI से ढका है। लॉन्चर स्वयं interpreter-खोज पर दस जाँचों से ढका है, जहाँ वह पहले गलत हुआ है। 1.0 से पहले इंटरफ़ेस बदल सकते हैं।

## यह क्यों मौजूद है

Laya चुपचाप चीज़ें काटता है और उनमें से कुछ भी रिपोर्ट नहीं करता:

- **यह state को अंत से काटता है।** लंबा दस्तावेज़ अपनी पूँछ खो देता है — किसी अनुबंध या ईमेल थ्रेड के लिए अक्सर वहीं उत्तर होता है — और मॉडल बचे हुए अग्रभाग पर पूरे भरोसे के साथ उत्तर देता है।
- **यह विकल्पों को तब तक छोटा करता है जब तक लेबल अलग-अलग पहचाने न जा सकें।** विकल्प प्रति-प्रश्न एक निश्चित टोकन बजट साझा करते हैं; एक बिंदु के बाद हर लेबल को ~4 टोकन मिलते हैं। यह उच्च-कार्डिनैलिटी विकल्पों पर उसके पतन का प्रलेखित कारण है।
- **इसका `confidence` सटीकता नहीं है।** यह एक सामान्यीकृत एंट्रॉपी है: प्रायिकता बिखरी होने पर कम — भले शीर्ष विकल्प सही हो — और आत्मविश्वास से गलत उत्तर पर ज़्यादा।
- **CUDA OOM पर यह स्वयं को CPU पर उतार देता है**, स्थायी रूप से, कोई फ़्लैग सेट किए बिना — लगभग 10-15 गुना धीमा, और उत्तर में कुछ भी यह नहीं कहता।

यह पैकेज वह जोड़ता है: एक preflight जो बताता है क्या कटेगा, संरचित त्रुटियाँ जो दोषी प्रश्न का नाम लेती हैं, एक ईमानदार confidence अनुबंध, और एक स्वास्थ्य सतह जो अवनति स्वीकार करती है।

## उपयोग

```bash
laya-mcp serve      # 127.0.0.1:8787 पर गर्म HTTP sidecar (मॉडल एक बार लोड करता है)
laya-mcp mcp        # stdio पर MCP
laya-mcp doctor     # क्या स्थापित है, और क्या GPU वास्तव में काम करता है
laya-mcp install    # आपके पास जो भी agent harness हो उसमें पंजीकृत करें
```

`install` इस तथ्य को सँभालता है कि MCP सर्वर पंजीकृत करने का कोई पोर्टेबल तरीक़ा नहीं है: Claude Code (`mcpServers`), Codex (`[mcp_servers.<name>]`), opencode (`mcp`, `command` array के साथ), OpenClaw (`mcp.servers`) और Hermes (`mcp_servers`) — हर एक को सही फ़ाइल में सही आकार मिलता है, मिलाकर और बैकअप लेकर, न कि मिटाकर। `pi` में मूल MCP समर्थन नहीं है और उसे असमर्थित बताया जाता है।

हर stdio प्रक्रिया में मॉडल रखने के बजाय `serve` के साथ `--sidecar` पसंद करें: एक harness प्रति सत्र एक सर्वर बनाता है, और प्रति सत्र 650 MB का checkpoint लोड करना ही वह मुख्य कारण है जिससे Python-आधारित MCP सर्वर धीमा लगता है।

## ईमानदार सीमाएँ

अपस्ट्रीम के स्वयं के आँकड़े, दोहराए गए क्योंकि जो एकीकरण इसके विपरीत संकेत देता है वह आपसे झूठ बोल रहा है: आधार checkpoints टाइप किए निर्णयों पर **zero-shot में संयोग के क़रीब** हैं (0.362, बहुसंख्यक-वर्ग आधार रेखा 0.461 के विरुद्ध); `score` सबसे कमज़ोर primitive है (स्वतंत्र मापन में 35% बनाम 70%); तापमान फ़िट करने से पहले कच्ची अंशशोधन त्रुटि 0.466 है; और एक fixture रन ने 50 बहुविकल्पीय मदों में से 46 में «A» उत्तर दिया।

अंशशोधन प्रायिकता को ईमानदार बनाता है; यह मॉडल को सही नहीं बना सकता।
